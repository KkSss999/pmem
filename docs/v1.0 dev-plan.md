# v1.0 开发计划

> 基于 `docs/v1.0 pre-design.md` 的两层架构设计，将现有能力重构为 Runtime + 保持上层产品体验不变。

### 已做好的事情

- CLI → core 的委托模式已经建立（v0.8 消除了之前 command 内重复实现）
- MCP 和 CLI 已经调同一套 `core/query/*` 函数
- query engine（intent/candidates/scoring/pack）已经是纯函数 + 可测试架构

### 还没做的事情（v1.0 要做的）

- **没有 Runtime 对象**：一切都是 `pmemPath` 作为第一参数的函数，不是 `memory.ask()` 形式的对象方法
- **没有 scope / policy engine**：无 namespace、scope 管理、策略评估、事件存储
- **没有 SDK 导出**：`src/index.ts` 是 CLI 二进制入口，`package.json` 没有 `exports` 字段给 SDK 用
- **数据库是单例**：`src/core/db.ts` 的 `_db` 模块变量只能开一个库
- **commands/ 里仍有非委托逻辑**：路径解析、存在性检查、格式化输出散落在每个 command 文件里
- **types.ts 臃肿**：701 行，所有类型堆在一个文件里


**验证**：`npm run build && npm test` 全绿。

### 步骤 2：数据库去单例化

**文件**：`src/core/db.ts`

**内容**：
1. 删除模块级 `let _db: Database.Database | null = null`
2. `openDatabase(pmemPath)` 改为每次创建新实例（或加 `createDatabase(pmemPath): Database`）
3. `closeDatabase(db)` 接受参数而非操作全局变量
4. `getDatabase()` 删除或改为接受 pmemPath 参数
5. 所有调用方（commands/、core/query/、mcp/）传入 db 实例

关键 diff：

```ts
// 旧
let _db: Database.Database | null = null;
export function openDatabase(pmemPath: string): Database.Database {
  if (_db) return _db;
  // ...
}

// 新
export function openDatabase(pmemPath: string): Database.Database {
  // 每次都创建新实例，调用方负责生命周期
  const dbPath = path.join(pmemPath, 'pmem.db');
  const db = new Database(dbPath);
  db.pragma('journal_mode = WAL');
  db.pragma('foreign_keys = ON');
  return db;
}
```

**影响范围**：约 30+ 文件需要适配（commands/*、core/query/*、core/capture.ts、core/consistency.ts 等）。

**验证**：`npm test` 全绿，尤其数据库相关测试。

### 步骤 3：实现 Runtime 层

这是 v1.0 核心工作。新增 `src/runtime/` 目录。

#### 3a. `src/runtime/types.ts` — Runtime 类型

```ts
// Pmem.open() 的入参
interface PmemOpenOptions {
  root: string;           // 项目根目录
  preset?: string;        // 默认 "software"
  config?: Partial<RuntimeConfig>;  // 覆盖 preset 中的字段
}

// Pmem 实例暴露的 API
interface PmemInstance {
  root: string;
  config: RuntimeConfig;

  // 查询（复用现有 core/query/*）
  ask(query: string, opts?: AskOptions): Promise<AskResultV03>;
  recall(opts?: RecallOptions): Promise<RecallResult>;
  context(task: string, budget?: number): Promise<ContextQueryResult>;
  related(id: string, opts?: RelatedOptions): Promise<RelatedResult>;
  status(opts?: StatusOptions): Promise<StatusResult>;

  // 写入
  observe(change: Observation): Promise<Receipt>;
  capture(summary: string, opts?: CaptureOptions): Promise<CaptureResult>;
  endSession(result: SessionResult): Promise<void>;

  // 生命周期
  close(): Promise<void>;
}
```

#### 3b. `src/runtime/config.ts` — 配置加载

```ts
// 从 manifest.yml 加载 preset → 合并用户覆盖 → 产出 RuntimeConfig
export function loadRuntimeConfig(root: string, preset?: string, overrides?: Partial<RuntimeConfig>): RuntimeConfig {
  const manifest = loadManifest(path.join(root, '.pmem'));
  const resolved = resolveConfig(manifest);

  // preset 默认值
  const defaults = PRESET_DEFAULTS[preset || 'software'];

  return deepMerge(defaults, overrides || {});
}

const PRESET_DEFAULTS: Record<string, Partial<RuntimeConfig>> = {
  software: {
    defaultScope: 'project',
    branchAware: true,
    working: { ttl: '12h' },
    episodic: { capture: 'automatic' },
    durable: { format: 'markdown', confirmation: 'required' },
  },
  research: { /* ... */ },
  novel: { /* ... */ },
};
```

#### 3c. `src/runtime/scope.ts` — Scope 管理

```ts
// scope 树：project → branch → session → agent → private
export class ScopeManager {
  constructor(root: string, config: RuntimeConfig);

  resolve(file: string, change: Observation): string;     // 推断 scope
  isVisible(scope: string, principal: string): boolean;   // 可见性判断
  children(scope: string): string[];                      // 子 scope
}
```

v1.0 的 scope 实现保持简单——不做复杂的 namespace 隔离（那是 v1.1 的事）。v1.0 只需要：
- `project` scope（默认）
- `branch` scope（当 manifest `branch_aware: true` 时，根据 git branch 自动切换）
- `session` scope（捕获时自动关联当前 session）

#### 3d. `src/runtime/policy.ts` — Policy Engine

```ts
export class PolicyEngine {
  constructor(config: RuntimeConfig);

  // 判断是否需要确认
  requiresConfirmation(memory: MemoryProposal): boolean;

  // 判断是否应该蒸馏
  shouldDistill(card: MemoryCard, traceCount: number): boolean;

  // 判断是否过期
  isExpired(card: MemoryCard): boolean;

  // 判断是否是重复内容
  isDuplicate(proposal: MemoryProposal, existing: MemoryCard[]): boolean;
}
```

v1.0 policy engine 不暴露给用户配置，所有策略由 preset 自动配置。

#### 3e. `src/runtime/event-store.ts` — Event Store

```ts
// SQLite backed append-only event log
export class EventStore {
  constructor(db: Database.Database);

  append(event: MemoryEvent): void;
  replay(since?: string): MemoryEvent[];    // 按时间回放
  working(scope: string): WorkingMemory;   // 当前 working memory
  expire(): void;                           // 清理过期的 working memory
}

type MemoryEvent =
  | { type: 'observe'; scope: string; ... }
  | { type: 'commit'; scope: string; ... }
  | { type: 'supersede'; scope: string; ... }
  | { type: 'forget'; scope: string; ... };
```

event store 用现有 `update_log` 表扩展（或新建 `events` 表）。

#### 3f. `src/runtime/index.ts` — Pmem 类

```ts
export class Pmem implements PmemInstance {
  readonly root: string;
  readonly config: RuntimeConfig;
  private db: Database.Database;
  private scope: ScopeManager;
  private policy: PolicyEngine;
  private events: EventStore;

  static async open(opts: PmemOpenOptions): Promise<Pmem> {
    const config = loadRuntimeConfig(opts.root, opts.preset, opts.config);
    const db = openDatabase(path.join(opts.root, '.pmem'));
    createSchema(db);
    return new Pmem(opts.root, config, db);
  }

  private constructor(root: string, config: RuntimeConfig, db: Database.Database) {
    this.root = root;
    this.config = config;
    this.db = db;
    this.scope = new ScopeManager(root, config);
    this.policy = new PolicyEngine(config);
    this.events = new EventStore(db);
  }

  // 查询方法直接委托给 core/query/*，传入 this.db
  async ask(query: string, opts?: AskOptions): Promise<AskResultV03> {
    return askQuery(this.db, this.root, query, { ...opts, now: Date.now() });
  }

  async recall(opts?: RecallOptions): Promise<RecallResult> {
    return recallQuery(this.db, this.root, opts);
  }

  async context(task: string, budget?: number): Promise<ContextQueryResult> {
    return contextQuery(this.db, this.root, task, budget);
  }

  // 写入方法：先经过 policy engine 再执行
  async observe(change: Observation): Promise<Receipt> {
    const scope = this.scope.resolve(change.file || '', change);
    this.events.append({ type: 'observe', scope, ...change });
    // policy 决定是否生成 trace、是否标记 dirty
    // ...
  }

  async capture(summary: string, opts?: CaptureOptions): Promise<CaptureResult> {
    // 调 core/capture.ts，但加入 policy 判断
  }

  async endSession(result: SessionResult): Promise<void> {
    // policy 判断是否 distill、哪些过期
  }

  async close(): Promise<void> {
    closeDatabase(this.db);
  }
}
```

**关键设计决策**：
- `Pmem.open()` 是异步工厂方法（为未来 Rust backend 预留 async 签名）
- 查询方法直接委托给现有 `core/query/*`，不重写
- 写入方法在现有 `core/capture.ts` 等基础上加 policy 包装
- v1.0 的 scope/policy 保持最小化——不暴露给用户，只内部分层

### 步骤 5：重构 CLI 层

**文件**：`src/index.ts` + 全部 `src/commands/*.ts`

**内容**：每个 command 改为 `Pmem.open()` → `memory.xxx()` → 格式化输出。

旧模式：
```ts
// src/commands/ask.ts
export function askCommand(query: string, format: CliFormat, options: AskCommandOptions): void {
  const cwd = process.cwd();
  const pmemPath = path.join(cwd, '.pmem');
  // 存在性检查...
  const result = askQuery(pmemPath, query, { explain, limit });
  // 格式化输出...
}
```

新模式：
```ts
// src/commands/ask.ts
export async function askCommand(query: string, format: CliFormat, options: AskCommandOptions): Promise<void> {
  const memory = await Pmem.open({ root: process.cwd() });
  try {
    const result = await memory.ask(query, { explain: options.explain, limit: options.limit });
    // 格式化输出（不变）
  } finally {
    await memory.close();
  }
}
```

**格式化和输出逻辑不**——只把数据获取从直接函数调用改为 `memory.xxx()`。

### 步骤 6：重构 MCP Server

**文件**：`src/mcp/server.ts`

**内容**：启动时 `Pmem.open()` 一次，整个 server 生命周期复用同一实例。

```ts
export async function startMcpServer(pmemPath: string, writeMode: 'readonly' | 'append-only' = 'readonly'): Promise<void> {
  const memory = await Pmem.open({ root: pmemPath });

  server.setRequestHandler(CallToolRequestSchema, async (request) => {
    switch (name) {
      case 'pmem_ask':
        result = await memory.ask(args.query);
        break;
      case 'pmem_recall':
        result = await memory.recall({ since: args.since });
        break;
      case 'pmem_context':
        result = await memory.context(args.task, args.budget);
        break;
      case 'pmem_capture':
        result = await memory.capture(args.summary, { next: args.next });
        break;
      // ...
    }
  });
}
```
